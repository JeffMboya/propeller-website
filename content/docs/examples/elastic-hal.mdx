A WebAssembly component example using the [Elastic HAL](https://github.com/elasticproject-eu/wasmhal) `elastic:hal/attestation@0.1.0` interface. The component requests a TEE attestation report and returns the evidence as bytes. It runs via `hal-runtime`, which provides the HAL host functions to the component.

> **Elastic HAL vs HAL Test**
>
> Propeller has two HAL examples that serve different purposes:
>
> - [HAL Test](./hal-test) uses the older `elastic:tee-hal/*` C-ABI interface (wasip1). It runs end-to-end through the Propeller task pipeline today using `PROPLET_HAL_ENABLED=true`.
> - **This example** uses the newer `elastic:hal/*` WIT component model interface (wasip2). It reflects the direction the [wasmhal](https://github.com/elasticproject-eu/wasmhal) project is heading but runs via `hal-runtime` directly — the proplet's wasmtime linker does not yet provide `elastic:hal` host imports for the component model path.
>
> If you want to run a HAL workload through the Propeller task pipeline today, start with [HAL Test](./hal-test).

## Prerequisites

Build `hal-runtime` from [wasmhal](https://github.com/elasticproject-eu/wasmhal) at commit `cfe99ef`:

```bash
git clone https://github.com/elasticproject-eu/wasmhal.git
cd wasmhal && git checkout cfe99ef41f369d35bc04a049b47d32951cb19981
cd hal-runtime && cargo build --release
```

## Build

```bash
cd propeller
make attestation-test
```

Your output should look like this:

```bash
cd examples/attestation-test && cargo build --target wasm32-wasip2 --release
    Finished `release` profile [optimized] target(s) in 0.40s
cp examples/attestation-test/target/wasm32-wasip2/release/attestation_test.wasm build/attestation-test.wasm
```

## Running Inside an Intel TDX CVM

Inside a Confidential VM with Intel TDX, the HAL detects the hardware environment and all four TDX indicators are confirmed. Load the TDX guest driver first, then run the component:

```bash
sudo modprobe tdx-guest
hal-runtime ./attestation-test.wasm
```
